# wb_stocks — остатки Wildberries по списку артикулов

Читает артикулы из `шаблон_артикулы.xlsx`, опрашивает Wildberries и сохраняет
отчёт `Остатки_WB_<дата>.xlsx` рядом с программой.

## Что было сломано

Все запросы получали `403 Forbidden`, все 859 артикулов уходили в ошибку.
Причина не в одном месте, их накопилось четыре:

| Причина | Было | Стало |
|---|---|---|
| Запрос шёл без кук с витрины WB | сразу на `card.wb.ru` | сессия прогревается на `www.wildberries.ru`, куки едут в запрос |
| Единственный зашитый эндпоинт и `dest` | `card.wb.ru/cards/v2/detail` намертво | подбор из 5 эндпоинтов, `dest` спрашивается у гео-сервиса WB |
| Пачка по 100 артикулов — выше лимита WB | 100 в запросе | 50 по умолчанию, дальше подстраивается сам |
| Один TLS-отпечаток на весь прогон | один профиль | 6 профилей `curl_cffi`, ротация при блокировке |

Плюс к этому: пачка при отказе дробится пополам, так что один «плохой»
артикул больше не уносит в ошибку остальные 49; неудачи пишутся в
`wb_stocks.log` целиком, а не обрезанной строкой в консоли.

## Запуск

```
pip install -r requirements.txt
python wb_stocks.py
```

## Как получить exe

PyInstaller не умеет кросс-компиляцию: exe собирается только на Windows.
Два способа.

**На своём компьютере.** Нужен [Python 3.11+](https://www.python.org/downloads/),
при установке отметьте «Add Python to PATH». Дальше двойным щелчком по
`build.bat`, результат — `dist\wb_stocks.exe`.

Руками это две команды:

```
python -m pip install curl_cffi openpyxl pyinstaller
python -m PyInstaller --onefile --console --name wb_stocks --collect-all curl_cffi --collect-all openpyxl wb_stocks.py
```

Именно `python -m PyInstaller`, а не голое `pyinstaller`: папка `Scripts`,
куда pip кладёт exe-обёртки, часто отсутствует в PATH, и команда не находится.
Заглавные `P` и `I` обязательны — имя модуля регистрозависимо. Если и `python`
не распознан, замените его на `py`, а если Python только что установлен —
закройте и откройте консоль, старое окно о новом PATH не знает.

**Через GitHub Actions**, если Python ставить не хочется. Сборка идёт на
Windows-машине GitHub: вкладка Actions → «Сборка wb_stocks.exe» → Run workflow,
через пару минут готовый exe лежит в артефактах запуска. Workflow запускается
и сам при каждом изменении `wb_stocks.py`.

Флаг `--collect-all curl_cffi` в сборке обязателен: без него в exe не попадают
библиотеки libcurl, подмена TLS-отпечатка молча отключается и 403 возвращается.

## Файл с артикулами

Рядом с программой — `шаблон_артикулы.xlsx`. Если его нет, берётся первый
подходящий `.xlsx`, `.csv` или `.txt` в папке. Годятся числа, строки и ссылки
вида `https://www.wildberries.ru/catalog/123456789/detail.aspx`, в любом
столбце и на любом листе; дубли и мусор отсеиваются сами.

## Отчёт

Столбцы: артикул, статус, остаток, источник, название, бренд, продавец, цена,
комментарий, ссылка. Цвет строки — статус:

- зелёный — в продаже;
- жёлтый — карточка есть, остаток нулевой;
- красный — нет на сайте;
- серый — проверить не удалось, причина в столбце «Комментарий».

## Прокси

Самый простой способ — файл `proxy.txt` рядом с программой, по одному адресу
в строке (строки с `#` игнорируются):

```
# как отдают продавцы: IP:порт:логин:пароль
185.12.34.56:8000:user12:pass34
# или привычным URL
socks5://user12:pass34@185.12.34.57:1080
```

Понимаются форматы `host:port`, `host:port:user:pass`, `user:pass@host:port`
и полный URL с `http://`, `https://`, `socks5://`.

**Про HTTP и SOCKS5.** Если протокол в строке не указан, адрес проверяется
и как HTTP, и как SOCKS5 — угадывать молча нельзя, неверный протокол выглядит
точно так же, как мёртвый прокси. Нерабочий вариант отсеется сам, в итогах
проверки будет видно, какой сработал. Когда протокол известен, пишите его
явно: так на один лишний запрос меньше.

```
185.12.34.56:8000:user12:pass34              # проверим оба протокола
http://user12:pass34@185.12.34.56:8000       # только HTTP
socks5://user12:pass34@185.12.34.57:1080     # только SOCKS5
```

SOCKS5 поднимается до `socks5h`, чтобы домены резолвил прокси, а не ваш
провайдер — для обхода блокировок это существенно. Альтернативы: ключ `proxy`
(или список `proxies`) в `wb_config.json`, либо переменная `WB_PROXY`.

На старте программа показывает, с какого IP реально пойдут запросы:

```
Прокси: 2 шт — http://185.12.34.56:8000 и другие
Внешний IP: 185.12.34.56, страна RU (http://185.12.34.56:8000)
```

Если страна не RU — будет предупреждение: у WB такой адрес не пройдёт.
Мёртвый прокси пропускается автоматически, работа продолжается на следующем.
При блокировке адрес меняется вместе с сессией и куки набираются заново —
менять IP, не обновив куки, бессмысленно: это тот же 403.

Пароли в консоли и логе скрыты, в репозиторий `proxy.txt` не попадает.

### Быстрая проверка прокси

Не гоняйте все артикулы, чтобы понять, годится ли купленный адрес.
Положите его в `proxy.txt` и запустите `test-proxy.bat` — около десяти
секунд и понятный вердикт по каждому каналу:

```
  http://185.12.34.56:8000: РАБОТАЕТ
  http://185.12.34.57:8000: WB БЛОКИРУЕТ (HTTP 403)
  прямое подключение: WB БЛОКИРУЕТ (HTTP 403)
```

Проверка идёт на вашем первом артикуле из файла и показывает по каждому
каналу внешний IP со страной, ответ витрины, набранные куки и результат
боевого запроса карточки. Прямое подключение проверяется заодно — полезно
знать, изменилось ли что-то без прокси.

Из командной строки то же самое: `wb_stocks.exe --test`.

Батники намеренно написаны латиницей и с CRLF-переводами строк: cmd.exe
не выполняет файлы с юниксовыми переводами строк — окно открывается
и мгновенно закрывается. За этим следит `.gitattributes`.

Важно, что означает сплошное «WB БЛОКИРУЕТ» при живом российском прокси:
дело не в адресе. Значит, режется сам тип запроса, и покупка ещё одного
прокси ничего не изменит — нужен другой источник данных.

### Какой прокси брать

Для 859 артикулов это ~18 запросов за прогон, поэтому дорогой ротируемый пул
не нужен. По возрастанию цены:

1. **Российский IPv4 дата-центр** (~100–200 ₽/мес за адрес) — с такой нагрузкой
   обычно хватает. Начинать стоит отсюда.
2. **Резидентный RU** — если дата-центр выбило. Берите тариф со **sticky-сессией**
   минут на 10: при ротации IP на каждом запросе куки витрины слетают и 403
   возвращается.
3. **Мобильный RU** (МТС, Мегафон, Билайн, Tele2) — самый устойчивый: за одним
   адресом сидят тысячи живых абонентов, и WB не может забанить его без ущерба
   для себя. Нужен, только если не помогло предыдущее.

IPv4, не IPv6: на IPv6 WB отвечает неохотно. Бесплатные списки прокси не берите —
они мертвы, медленны и часто чужие. Токен продавца через прокси идёт внутри
HTTPS, так что посредник видит только имя хоста.

## Настройки (необязательно)

`wb_config.json` рядом с программой:

```json
{
  "token": "",
  "proxy": "",
  "proxies": [],
  "dest": "",
  "batch_size": 50,
  "delay": 0.4,
  "input_file": ""
}
```

- `proxy` / `proxies` — то же, что `proxy.txt`, если удобнее держать в конфиге.
- `token` — ключ Statistics API продавца. Можно положить в `token.txt` или в
  переменную `WB_API_TOKEN`. Официальный API не блокируется и отдаёт остатки
  своих товаров даже когда публичный API лёг целиком — это самый надёжный путь,
  но он покрывает только ваш собственный ассортимент.
- `dest` — код региона, если нужен конкретный склад. Пусто — определится сам.
- `batch_size` — артикулов в одном запросе. Больше 50 ставить не стоит.
- `delay` — пауза между запросами в секундах.
- `input_file` — путь к файлу с артикулами, если он лежит не рядом.

## Если снова 403

Программа напечатает, какие комбинации перебрала, и назовёт вероятные причины.
Порядок проверки:

1. Посмотрите строку «Внешний IP» в начале вывода. Страна не RU — дело в ней,
   остальное проверять смысла нет.
2. Откройте `https://www.wildberries.ru` в браузере на этом же компьютере.
   Не открывается — дело в сети, а не в программе.
3. Загляните в `wb_stocks.log` — там полный протокол с кодами ответов и
   началом тела каждого отказа.
4. Если WB снова переехал, новый адрес добавляется одной строкой в
   `CARD_ENDPOINTS` в начале `wb_stocks.py`.
